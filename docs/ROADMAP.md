# Test Workbench Roadmap

## 产品定位

Test Workbench 是面向个人网络设备测试工程师的本地测试记录闭环平台，服务于 ONU、OLT、光猫等设备的手工测试。当前版本定义为 **V1 Alpha**，不是完整 V1，也不是自动化测试平台。

V1 持续遵守以下边界：

- 单用户、本地运行
- 以手工测试和过程追溯为核心
- 不包含 AI、多用户权限、企业协作、云端部署
- 不执行自动化脚本，不引入复杂工作流引擎

## Sprint 0–4 完成状态

| Sprint | 主题 | 状态 | 已交付能力 |
|---|---|---|---|
| Sprint 0 | Foundation | 已完成 | React、FastAPI、SQLite、ORM、Alembic、配置、日志和测试基础 |
| Sprint 1 | Device Library | 已完成 | ONU/OLT/光猫设备档案 CRUD |
| Sprint 2 | Test Case Library | 已完成 | 测试用例、步骤、优先级和启停管理 |
| Sprint 3 | Test Execution | 已完成 | 测试项目、DUT选择、用例选择、手工执行、结果与历史快照 |
| Sprint 4 | Defect & Regression | 已完成 | 缺陷生命周期、失败证据关联、追加式回归和状态联动 |

当前核心链路已经形成：

```text
设备档案
→ 测试用例
→ 测试项目
→ 测试执行
→ PASS/FAIL/BLOCKED
→ 缺陷
→ 回归
```

## V1 Alpha 定义

V1 Alpha 已具备结构化记录和缺陷回归闭环，可用于验证核心数据模型与日常操作方式。

V1 Alpha 当前仍存在以下生命周期断点：

- 测试结果和缺陷缺少截图、日志、配置文件等证据
- 已完成结果的完整性规则仍需加强
- 未记录并冻结 OLT、PON口、VLAN、拓扑等测试环境
- 尚不能生成测试报告、归档项目或验证数据恢复

因此，V1 Alpha 适合内部持续使用和流程验证，但不作为完整 V1 验收版本。

## Sprint 5–7 规划

### Sprint 5 — Test Evidence & Result Integrity

目标：补齐测试证据链，并确保已完成结果不会因后续编辑失真。

计划方向：

- 完善 RunResult 完成与不可变规则
- 加强 SQLite 外键和关联完整性
- 为 RunResult、Defect 管理截图、日志、配置文件等本地附件
- 补充实际结果、失败现象或 BLOCKED 原因等必要记录
- 保持附件元数据与本地文件的一致性

不包含自动采集、日志分析、AI分析或自动化执行。

### Sprint 6 — Environment Snapshot

目标：记录可复用的测试环境，并在创建 TestRun 时生成不可变环境快照。

计划方向：

- 环境档案的创建、编辑、查看和选择
- 记录拓扑、OLT/板卡/PON口、VLAN、WAN模式及必要业务参数
- 创建 Run 时冻结环境数据和快照版本
- 历史 Run 不受环境档案后续修改影响

不包含自动发现设备、自动下发配置或拓扑探测。

### Sprint 7 — Report & Archive

目标：将项目、执行、缺陷和证据汇总为可交付测试结论，并支持本地归档。

计划方向：

- 汇总项目版本、DUT、环境快照、执行结果、缺陷和回归
- 计算通过率、结果分布和遗留缺陷等基础统计
- 导出本地测试报告
- 归档已完成项目并保持历史可读
- 提供最低限度的数据备份与恢复验证

不包含企业审批、在线分享、协作评论或云端归档。

## 完整 V1 验收标准

完整 V1 必须同时满足：

1. **生命周期闭环**：需求/版本、DUT、用例、环境、执行、证据、缺陷、回归、报告和归档可以连续追溯。
2. **历史可信**：设备、用例、环境快照不可修改；完成后的执行结果不能被覆盖；回归记录只追加。
3. **证据完整**：截图、日志和配置文件能够关联到具体结果或缺陷，文件缺失时有明确提示。
4. **环境可复现**：每次 Run 都能查看当时使用的环境快照，不依赖当前环境档案。
5. **结果可交付**：能够输出包含结果统计、失败项、缺陷和回归结论的测试报告。
6. **归档可恢复**：已完成项目可归档、查询，并完成至少一次本地备份与恢复验证。
7. **质量基线**：数据库迁移、后端测试、前端测试和生产构建全部通过，项目文档与当前实现一致。
8. **范围受控**：不引入 AI、多用户、企业协作、自动化执行、复杂工作流或云端部署。
