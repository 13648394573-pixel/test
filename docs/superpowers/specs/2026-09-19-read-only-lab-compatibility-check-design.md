# ONU 现场只读兼容性检查设计

## 1. 文档状态

- 设计日期：2026-09-19
- 功能名称：现场只读兼容性检查
- 目标版本：V2 首个真实 Skill 的实验室验证准备阶段
- 当前状态：设计已确认，等待实施计划
- 关联 Skill：`ONU_REGISTRATION_DUAL_WAN_CONNECTIVITY`
- 关联主设计：`2026-09-18-onu-registration-dual-wan-skill-design.md`

本功能是“ONU 注册与双 WAN 联网验证 Skill”的前置兼容性检查，不是第二套测试执行系统。它用于在任何 OLT 配置变更发生前，验证测试电脑、Huawei MA5800-X7 只读查询、ONU Web 页面适配器和本地证据保存能力是否适合进入正式实验室测试。

## 2. 与既有方案的一致性

本设计不改变下列已确认范围：

- 正式 Skill 仍覆盖 ONU 自动发现、注册、IPoE/PPPoE 下发、取址、分别联网验证和恢复。
- 正式 Skill 仍支持顺序隔离和双 WAN 同时下发，由测试人员在启动时选择。
- E1 至 E6 六组核心证据、版本化标准、PASS/FAIL/BLOCKED 判断和缺陷闭环保持不变。
- 仍以本地离线运行、双击启动、Windows 凭据保险箱和人工弹窗确认为最终交付方式。
- Huawei MA5800-X7 仍是首个 OLT，其他 OLT 通过后续适配器扩展。
- 不加入 AI 自动测试、自动登录未知设备、云平台、多用户权限或复杂自动化流程。

本检查提前实现主设计“预检与快照”和实施计划 Task 12 的只读验证门禁。检查通过不代表 ONU 功能 PASS，只代表当前环境具备继续验证正式 Skill 的基本条件。

## 3. 目标与成功条件

检查需要回答五个问题：

1. 本地 Workbench、证据目录和必要运行组件是否可用？
2. 是否能够安全连接指定 MA5800-X7，并识别主机指纹和命令提示符？
3. 只读 OLT 查询的输出能否被当前解析器识别并保存为脱敏证据？
4. 是否能够登录当前 ONU Web，并识别 WAN 页面和 Ping 页面所需控件？
5. 测试电脑指定网卡能否执行绑定源地址的基础 Ping？

成功条件不是产生产品测试结论，而是生成一份可复核的兼容性报告，明确哪些能力已经就绪、哪些需要补充现场参数、哪些被环境阻塞，以及是否允许进入正式 Skill 的配置变更阶段。

## 4. 方案选择

### 4.1 采用方案

采用 Workbench 内独立的“现场检查”浏览器页面，通过本地 API 调用现有 Runner 组件，并由专用只读编排器限制动作集合。

该方案适合非开发人员使用，能够复用现有凭据、证据和前端框架；正式 Skill 页面以后可以直接消费相同的预检结果和组件。

### 4.2 未采用方案

- 不采用命令行检查脚本作为主要入口：现场人员不容易填写参数、理解结果或处理凭据。
- 不直接嵌入正式 Skill 执行按钮：正式执行协调器尚未完成，且会混淆“适配器兼容”与“产品符合标准”。
- 不使用独立临时工具：会复制凭据、证据和通信逻辑，后续难以保持一致。

## 5. 安全边界

### 5.1 OLT 只读定义

“只读”指不会新增、删除、修改或保存 OLT/ONU 的持久配置。允许以下会话和查询动作：

- SSH 连接、固定主机指纹校验或首次显式确认。
- `enable`。
- `screen-length 0 temporary`，只影响当前 SSH 会话。
- `display ont autofind all`。
- `display ont info by-sn <SN>`。
- 已提供 F/S/P 和 ONT ID 时，查询 ONT、WAN 和 service-port 当前状态。
- 为执行只能在 GPON interface 视图运行的 `display` 命令，允许进入 `config` 和 `interface gpon 0/<slot>` 上下文；进入上下文本身不写入配置。
- 退出当前 CLI 上下文和关闭 SSH 会话。

专用执行器只能接受固定的只读动作代码和结构化参数。页面、API 和报告都不能提交或保存任意命令正文。

以下动作在该入口中必须不存在，即使已有正式 Runner 实现也不能注册到只读执行器：

- 注册或删除 ONT。
- 下发、删除或修改 IPoE、PPPoE、TR069 WAN。
- 新增、删除或修改 service-port。
- 修改 profile、VLAN、路由、认证或设备配置。
- 保存配置、重启设备或恢复快照。

任何试图调用非只读动作的请求都在建立 SSH 会话前被拒绝，并记录不含秘密的本地安全事件。

### 5.2 ONU Web 边界

- 只允许访问本地、私有或链路本地地址。
- 允许登录、导航、读取页面文本和截图。
- WAN 页面可以读取当前状态，但不会创建、编辑或删除 WAN。
- Ping 页面只验证导航和所需控件是否可识别，不点击开始按钮，不执行 ONU 侧 Ping。
- 所有截图前遮盖密码、账号、Token、LOID 等敏感控件，页面文本再次执行脱敏。

### 5.3 电脑侧边界

- 允许查询本机网卡、地址和状态。
- 允许从测试人员指定的本地源地址运行 Windows Ping。
- 不修改默认路由、接口 metric、DNS、网卡启停状态或防火墙。
- 不要求访问互联网；目标可以是实验室内网地址。公网目标只有在测试人员明确填写时才执行。

## 6. 页面与交互

Workbench 增加“现场检查”模块，使用四步向导：

1. **填写目标**：OLT 地址和端口、主机指纹、凭据引用、ONU SN、可选 F/S/P 与 ONT ID、ONU Web 地址、ONU Web 凭据引用、电脑网卡、源地址和 Ping 目标。
2. **检查凭据**：只显示凭据是否存在；允许将秘密写入 Windows 凭据保险箱，但不回显秘密。
3. **执行检查**：按阶段显示当前状态，前一项阻塞不会触发危险的替代动作。可独立重试安全阶段。
4. **查看报告**：显示就绪判断、阻塞原因、人工处理建议和证据文件。

页面必须醒目标明“本流程不会注册 ONU、不会下发 WAN、不会修改 OLT 配置”。运行按钮旁显示本次允许执行的查询范围。

## 7. 执行阶段与数据流

### 7.1 阶段顺序

1. 本机运行环境和证据目录检查。
2. 参数格式、私有地址、凭据引用和主机指纹检查。
3. OLT SSH 连接和提示符识别。
4. OLT autofind 查询、解析、脱敏文本保存和终端 PNG 生成。
5. 若提供 SN，查询当前注册信息。
6. 若提供 F/S/P 与 ONT ID，查询当前 ONT、WAN 和 service-port 信息。
7. ONU Web 登录、WAN 页面读取与截图。
8. ONU Web Ping 页面选择器检查，不运行 Ping。
9. 电脑指定网卡和源地址检查，并执行基础 Ping。
10. 汇总兼容性报告和进入正式 Skill 的建议。

### 7.2 组件边界

- `ReadOnlyLabValidator`：只负责阶段编排和状态汇总。
- `ReadOnlyMA5800Executor`：维护比正式 Runner 更小的动作白名单，并委托现有 SSH transport 和 parser。
- `ONUWebCompatibilityProbe`：复用 Neutral ONU Web Surface，但提供不触发诊断按钮的页面能力检查。
- `PCProbe`：复用现有指定网卡 Ping，实现不做网络配置修改。
- `CompatibilityEvidenceStore`：复用现有证据写入、SHA256 和路径限制。
- 本地 API：接收结构化参数、启动一次检查、读取状态和报告；只允许 loopback 部署。
- 前端页面：不直接连接设备，只调用本地 API。

### 7.3 结果存储

兼容性检查不创建正式 `TestRun`、`Result`、`Defect` 或回归记录。每次检查创建独立的本地目录，保存：

- 脱敏后的请求参数快照，不含秘密值。
- 阶段事件和状态。
- OLT 原始脱敏文本及其终端 PNG。
- ONU Web 脱敏页面文本和截图。
- 电脑 Ping 文本及其终端 PNG。
- 带 SHA256 的兼容性 JSON 报告。

正式 Skill 后续可以引用最新一次兼容性报告的标识和哈希，但必须重新确认关键参数，不能把兼容性结论转换成产品 PASS。

## 8. 状态与错误处理

兼容性检查不使用正式产品 PASS/FAIL。单阶段状态为：

- `VERIFIED`：该能力在当前现场已成功验证。
- `NEEDS_INPUT`：缺少可选但继续该阶段所需的现场参数或凭据。
- `BLOCKED`：已提供必要条件，但连接、页面、解析器或本机能力无法完成检查。
- `NOT_RUN`：由于前置阶段未完成而没有执行。

总体状态为：

- `READY`：所有进入正式 Skill 所需能力均为 `VERIFIED`。
- `PARTIAL`：只读基础能力已验证，但某些依赖当前 ONU 状态的检查无法完成。
- `BLOCKED`：关键连接、安全校验、页面适配或证据保存能力不可用。

典型错误必须给出中文处理建议：主机指纹未知、OLT 凭据不存在、SN 未发现、WAN 尚不存在、ONU Web 登录失败、页面选择器不兼容、指定网卡未连接、Ping 输出无法识别、证据目录不可写。解析器不识别真实输出时保留脱敏原文用于后续 TDD 修正，不猜测结果。

## 9. API 边界

计划提供以下本地接口：

- `POST /api/lab-compatibility-checks`：创建并执行一次只读检查。
- `GET /api/lab-compatibility-checks/{check_id}`：读取阶段状态和总体结果。
- `GET /api/lab-compatibility-checks/{check_id}/evidence`：读取证据元数据。

首版采用同步逐阶段执行或可恢复的单次本地任务，不加入通用工作流引擎。响应不得包含秘密、任意命令正文、未脱敏原文或本地绝对路径。

## 10. 测试策略

实施必须测试驱动，先写失败测试，再写最小实现。至少覆盖：

- 只读执行器接受所有允许查询动作。
- 注册、删除、WAN 下发、service-port 修改和任意命令全部在连接前被拒绝。
- 缺少可选参数时返回 `NEEDS_INPUT`，不能误报 ONU FAIL。
- OLT 不可达、主机指纹不匹配、解析失败和分页异常均形成可理解的 `BLOCKED`。
- ONU Web 只导航和截图，绝不调用 Ping 开始动作或 WAN 保存动作。
- PC Probe 使用参数列表和指定源地址，不使用 shell，不修改系统网络配置。
- 凭据、PPPoE 信息和敏感页面字段不出现在数据库、日志、API 或证据中。
- API 仅在 loopback 配置下可用，非法私网目标和带凭据 URL 被拒绝。
- 前端清楚显示只读范围、阶段状态、人工建议和证据，不显示正式 PASS/FAIL。
- 完整后端测试、前端测试和生产构建继续通过。

## 11. 实施顺序与后续关系

本功能插入原实施计划 Task 7 与 Task 8 之间：

1. 建立只读领域模型、执行器和验证器。
2. 增加本地 API 和证据报告。
3. 增加“现场检查”浏览器页面。
4. 使用用户现场参数运行第一次真实只读检查。
5. 根据脱敏证据修正解析器或页面选择器。
6. 兼容性达到 `READY` 或用户接受的 `PARTIAL` 后，再继续正式 Skill 协调器、配置变更和 PASS/FAIL/BLOCKED 验证。

离线安装和双击启动仍由原计划 Task 11 统一交付；本页面不得另建一套安装器。真实只读检查仍需用户提供现场地址、凭据引用和连接状态，绝不使用文档示例值自动连接设备。

## 12. 验收标准

- 页面可由非开发人员填写现场参数并启动检查。
- 源码和运行时均不存在从该入口触发配置修改命令的路径。
- OLT、ONU Web、电脑网卡和证据能力分别给出清楚状态和处理建议。
- 每次检查生成脱敏、可校验、可追踪的本地证据报告。
- 检查不会创建正式测试结果、缺陷或报告归档记录。
- 既有 Skill 设计、E1 至 E6、双 WAN 选择、标准数据库和离线部署路线保持不变。
- 现场检查结果能够作为继续正式 Skill 验证的安全门禁。
