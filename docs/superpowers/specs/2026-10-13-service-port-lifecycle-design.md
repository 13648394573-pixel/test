# service-port 安全生命周期设计

日期：2026-10-13。代码基线：56272149489156bf1c911b59217e49f678008ae8。
状态：用户已同意总体方案，本文等待书面设计审核；未进入实施计划或编码。

## 1. 目标、范围与已确认事实

目标是补齐本地自动执行的业务通道管理：匹配则复用，缺失才创建，清理只针对
本次测试创建的资源。保持单机 B/S、既有 Router → Schema → Service →
Repository → Model 分层、Runner 白名单命令与人工审批机制。

现有 MA5800Actions/transport 支持查询和删除，不支持创建 service-port；
remove_test_services 只执行列表第一条。Coordinator 已把测试前快照中目标
ONT 的端口放入审批范围，但这不是测试资源所有权记录。现有完整 WAN 恢复
仍不支持。本设计不把上述修复或本次批准视为现场操作授权。

只处理 Huawei MA5800 的明确业务映射，不增加 LAN 绑定、NAT、DNS 功能测试、
拓扑、前端新模块或自动恢复原 WAN。不得修改旧 Run、Result、Snapshot 或
LOCKED 规则；不得重写旧执行计划。旧会话继续原计划，缺少新能力时停止，
不自动升级、补造资源账本或继续危险动作。

## 2. 方案选择与安全门禁

采用“精确复用 + 经审批创建 + 会话资源账本”。
全部删除重建会影响既有业务且依赖尚未支持的恢复能力；仅手工预配置不能
补齐自动通道创建。选定方案保留已有资源，并让新增资源有可核对的归属。

当前实现前提为保留已有注册的安全分支：按冻结 SN、FSP、ONT ID 核验注册
与 Profile，符合要求时跳过 DELETE_EXISTING/FREE_ID/REGISTER 等配置动作。
若身份、Profile 不匹配或注册缺失，返回明确 BLOCKED，不静默改用新 ID。
这项计划变化只用于新版本、新会话；不声称现有计划已经支持跳过注册。
对已注册目标，完整恢复未实现前不得先删除 ONT 再尝试建立业务通道。

## 3. 业务映射与配置来源

映射键：OLT 绑定身份、FSP、ONT ID、业务 VLAN、GEM port、用户 VLAN。
完整比较还包含 tag-transform、业务类型及创建命令涉及的其他固定属性。
VLAN/GEM 不能从示例端口、Profile 编号或 WAN IP-index 猜测；必须由经审核
的非敏感执行配置提供，并在创建新会话时冻结，缺失即拒绝执行。

当前 ServicePortObservation 只包含 ID/VLAN/FSP/ONT/GEM/user VLAN。
这不足以证明所有命令属性完全匹配；需要允许列表中的详情读取和严格解析。
无法确认完整属性、Profile 到 GEM 的适配、已有流量行为时 BLOCKED，不把
未知属性忽略后认定可以复用，也不自动修改 Profile/VLAN/上联配置。

多个业务可以引用同一映射。IPoE/PPPoE 共用 VLAN/GEM 映射时仅管理一条端口，
保留消费者列表；建立 service-port 不等于 WAN 地址或联网已经 PASS。
端口共享或复用时，顺序测试不得删除该端口来隔离 WAN，继续使用已有人工
隔离确认；未确认隔离时不得给出逐 WAN 的成功结论。

## 4. 数据、历史与接口

本阶段不新增数据库表，复用 ExecutionEvent 的追加式事件与幂等键；
ConfigurationSnapshot 保留原始测试前状态，后续查询形成独立事件和 Evidence。
资源账本是按 session_id 重放事件得到的视图，不修改原快照或参数快照。

资源事件 payload 版本为 1，包含：operation_id、mapping_key、完整映射、
service_port_id、origin（REUSED/CREATED）、consumers、审批 hash、基线
快照 hash、命令结果分类、前后查询 Evidence 引用、时间与状态。
允许的事件：PORT_REUSED、PORT_CREATE_INTENT、PORT_CREATE_VERIFIED、
PORT_CREATE_UNCERTAIN、PORT_DELETE_INTENT、PORT_DELETE_VERIFIED、
PORT_DELETE_UNCERTAIN、PORT_RETAINED。只有本会话已核验的 CREATED 资源
才拥有自动清理资格；其他会话创建、旧快照已有和临时新发现的都不算。

不增加公开任意命令 API；沿用现有创建、推进、审批响应和详情接口，详情
增加只读账本摘要。事件由 Repository 持久化，Service/Coordinator 决定策略，
Runner 负责白名单动作、现场核对、证据采集；不得让请求提供 owned=true
或 service-port 列表来代替账本。新执行计划增加版本与通道动作，已有
报告/归档继续读取冻结结果和 Evidence，不回写历史报告。

## 5. 创建与复用流程

1. 核验固定 SSH 指纹、目标 SN/FSP/ONT/Profile，查询完整目标端口清单。
2. 恰好一个完整匹配端口：记录 REUSED 和查询证据，不产生创建命令。
   重复匹配、冲突映射、解析不完整或无法确认范围均 BLOCKED。
3. 映射缺失时使用实验室配置中明确的候选 ID；通过按全局 ID 的只读查询
   确认未占用。未支持可靠查询时 BLOCKED，不仅凭目标 ONT 清单判断空闲。
   本阶段不开发全 OLT 自动分配器。候选占用时不自行换号。
4. 创建审批展示目标身份、全部映射属性、候选 ID、基线与查询 hash。
   明确展示 CREATE，不把既有端口编号当作待删除资源。
5. 审批后执行前重新核对身份、映射和候选 ID；变化使审批失效，停止并重新
   获取预览。进程内串行不等于锁住其他 OLT 操作者，不能宣称跨客户端原子性。
6. 先持久化 CREATE_INTENT，再调用参数化白名单命令；禁止字符串任意 CLI。
   命令返回后查询完整映射，成功响应加一致后验才记录 CREATE_VERIFIED。
   ID 冲突、超时或身份变化不报成功，不删除外部新占用资源。

设备 I/O 不在数据库长事务内。每个意图和结果各自短事务持久化；数据库
提交失败或进程中断时进入不确定状态，不能把设备命令当成数据库事务回滚。

## 6. 清理、KEEP 与恢复

生成清理集合时只选本会话 CREATE_VERIFIED 且不再被保留消费者引用的资源。
REUSED 永不自动删除；共享资源仍有消费者时不得删除。KEEP 明确保留本次
资源并追加 PORT_RETAINED，不顺带清理，不改变原资源归属。

清理预览包含完整集合、每条映射及创建事件引用。获批后逐条再次核验 SN、
FSP/ONT、ID、完整映射和账本，再持久化 DELETE_INTENT、删除、查询确认缺失。
所有条目逐条留证，不再只删除第一条。已缺失资源可记录已确认不存在；
参数漂移或无法确定归属立即停止。部分成功保留逐条结果，剩余项标为未处理，
不得报告整体清理 PASS，也不得自动删除 ONU 或“撤销”已删除端口。

清理本次端口不等于恢复原 WAN。RESTORE 仍明确返回完整恢复未支持，并转入
人工恢复任务；不得用只恢复注册替代完整恢复。若结束策略要求恢复所有配置，
必须在任何设备写入前 BLOCKED。选择 KEEP 也不能免除逐动作审批。

## 7. 幂等与中断处理

同一 operation_id 只持久化一个意图，不重复执行已核验成功的动作。
重启出现 INTENT 无最终结果时，标记 UNCERTAIN/RECOVERY_REQUIRED，并进行
只读核对，不自动再次创建或删除。若设备已存在预期映射但本会话未记录
CREATE_VERIFIED，不能仅凭一致就认领，须人工确认后续处置；不自动清理。
删除中断同样先只读查询，缺失则记录核对事实，存在则等待重新审批。

## 8. TDD 与验收标准

- 正常复用、缺失创建、同映射共享、不同映射分离；缺少完整属性必须拒绝。
- 同 ID 外部占用、重复映射、邻近 FSP/ONT、SN 或指纹变化、审批后配置变化。
- 创建/删除预览 hash 覆盖完整范围；旧 hash、篡改列表及跨会话资源均拒绝。
- 多条逐项清理、第二条失败、原有端口保留、共享引用仍在、KEEP 不删除。
- 命令超时、命令成功但查询不符、数据库失败、每个 I/O 前后进程中断。
- 事件重放与重试不重复写设备；UNCERTAIN 不自动认领或清理。
- 新旧执行计划兼容；旧 Snapshot、LOCKED Result、Report/Archive 校验不变。
- 完整后端、前端测试与构建回归；命令/解析测试使用脱敏离线替身。

离线通过不等于现场批准。真实写入验收必须另行批准具体目标和影响预览，
使用新 TestRun/独立验收库，先只读确认业务参数，再分别验收复用、创建、
逐条清理与中断门禁。原有资源保持不变、Evidence hash 可校验才通过；
不得用当前独立 Ping PASS 声称本生命周期或完整平台闭环已通过。

## 9. 实施影响与审核出口

预计影响：MA5800 白名单命令/解析/动作、Runner 绑定配置校验、skill catalog、
新执行计划和 Coordinator、现有事件 Repository 查询、相关测试与说明。
不修改 Device/TestCase、数据库结构、前端模块或现场历史数据。
新 API 响应字段与配置字段向后兼容；旧配置缺少创建参数时只允许能完整
核验的复用，否则明确 BLOCKED。不得默默补默认 GEM、ID 或 tag-transform。

本文自审要求：资源来源分离、审批与执行分离、I/O 与事务分离、清理与
完整恢复分离。完整恢复仍为后续独立能力，本方案不移除现有保护。
下一步由用户审核本文；批准后编写实施计划，再选择执行方式。当前不编码、
不执行迁移、不连接设备，不推送或合并 main。

## 10. Task 7 审批展示最小范围修订（2026-10-14）

实施期间发现新完整 PortPreview 未完整投影到实际 API，且现有前端无执行器审批消费者。用户已批准：修正 Router/Schema，并在现有测试执行页接入完整影响范围展示、审批响应及独立确认的单步推进。该修订只改变既有接口的安全呈现，不新增业务导航模块、会话创建能力、测试项、自动执行策略或数据库结构。

显示全部 CREATE/DELETE 项的目标、Profile、映射、消费者、候选 ID、创建事件、基线/读取 hash 及证据引用；无法核验预览返回 409，前端缺完整端口预览时禁止审批。只读取已有会话，不自动推进或 LOCK；明确点击推进可能产生既有流程设备 I/O，需另外取得具体现场授权。原有资源来源、清理资格、快照不可变和完整恢复 HOLD 规则不变。

## 11. 已确认的安全清理入口修订（2026-10-14）

用户批准并确认最小接线设计：增加 `POST /api/skill-executions/{id}/cleanup-preview`（严格空对象，仅查询及审计）与 `POST .../cleanup-execute`（仅 approved=true 与当前 preview_hash）。客户端不能提供端口、所有权、保留消费者或命令；服务端重放账本推导完整范围，沿用全局 ID 查询、完整审批、独立持久意图、真实证据和逐条缺失后验。

只对 v2、DEVELOPMENT、DRAFT、KEEP 会话开放，且必须处于 END_POLICY 待确认或 MANUAL_REQUIRED 恢复阶段。正常运行/创建、终态、LOCKED、未知/悬空资源均不授权清理；保留消费者取自已持久化 RETAINED 资源。创建或一般执行权限不随清理状态扩展。执行后仍 MANUAL_REQUIRED，不自动恢复 WAN、PASS、LOCK 或继续测试，原结束审批失效。

不改历史执行计划或快照；独立请求/启动/结果事件使最新预览、重复提交和中断可核查。已有最终结果的相同请求零额外 I/O；STARTED 无最终结果禁止重发，部分失败记录逐条结果与未处理项。范围仅既有清理核心、Service/API、现有页面组件与测试，无新数据库表/依赖/业务模块。此批准仅授权软件开发及离线验证，现场读写需分别另行授权。
